# Beat renderer (HyperFrames 0.9.13)

Renders a project one beat at a time, stitches the beats by stream copy, and re-renders only what a change touches. It rests on HyperFrames internals, so the version is pinned and anything else fails closed. An upgrade is a re-qualification.

Spec: `reports/2026-10-31-moves-plan-page/stage1/CONTRACT.md`. Measured results: `stage1/phase2-renderer.md`, and `BEAT-RENDER-RESULTS.md` for the spike. The spike's scripts are in `reports/2026-10-31-moves-plan-page/spike-scripts/`, kept as the record of how that evidence was made. They no longer run from there.

## Commands

Run from `the project root`.

```
python tools/beat_render/run.py draft  work/<id>/v2/editorial --profile review
python tools/beat_render/run.py change work/<id>/v2/editorial --profile review [--kind caption]
python tools/beat_render/run.py stitch work/<id>/v2/editorial --profile review
python tools/beat_render/run.py refs   work/<id>/v2/editorial --profile review
```

- `draft` renders every beat with no intact segment. `--force` renders all of them, replacing their segments.
- `change` compares the project to the last stitched picture and reports what `ownership.invalidate` touches. It renders every beat with no intact segment under its key, so going back to an earlier version reuses its exact segments. `--force` renders the touched beats anyway.
- `stitch` rebuilds the picture from segments, and refuses if any is missing or does not validate. It renders nothing, so a damaged segment needs `draft` or `change`, which replace it.
- `refs` captures every sample reference the store lacks, with no render. A new `events.json` adds sample frames.
- `--workers N` overrides `profiles.json`. A profile with `null` needs it.
- `--force` replaces segments, so an older stitched picture that used them stops validating. Nothing else replaces one.

All of them print a summary and write `beat/changes/NNNN.json`: what rendered, what was reused, retries, timings, the checks and status. The `sentinel_at_render` block is each segment as judged when it rendered. O5 in the checks is the result for this picture. A status of `FAIL` exits 1, a refusal exits 2, and missing references or a check that did not finish exit 3, because a review picture's best status is already UNVERIFIED.

**Order of a run.** The owner audit runs in the page first, and anything but PASS stops the run with nothing rendered. Then render, stitch, references, checks. `beat/current.json` moves only if both checks ran to the end and neither failed, and the entry carries the status. Any other picture goes in `beat/last_attempt.json`, so nothing reading `current.json` gets it, and `checks_unfinished` names a check that did not finish. `change` diffs against whichever is newer.

If O5 fails on a beat that did not render in this run, that beat's references are recaptured once and the output check runs again, recorded in `references_recaptured`. A bad reference clears. A bad segment fails the same way, because the fresh capture still disagrees with it.

## Checks

`draft`, `change` and `stitch` run Workstream C's two checks on every stitched picture. Exit 0 is PASS, 1 FAIL, 3 UNVERIFIED, and only 0 counts as a pass. Exit 4 means it never got to look: `conform.py` could not measure the page, or `output.py` had no file. `run.py` treats that, and a hang, as a check that did not finish.

```
python tools/beat_check/conform.py work/<id>/v2/editorial --all
python tools/beat_check/conform.py work/<id>/v2/editorial --beats b02,b03
python tools/beat_check/output.py work/<id>/beat/stitched/<name>/review.mp4
```

- `conform.py` measures the page against `events.json`, which the build writes. Reports go to `beat/checks/<rev16>/source.json`, with the file's hash in the name when `--render` names one. `--audit` is the owner audit alone, which `run.py` runs before it renders. On a `change` its scope is every touched beat, including one that reused its segment.
- The audit also watches the page build its timeline. A `to`, `from`, `set` or `fromTo` on it placed by anything but a number fails, whoever called it, shell included.
- `output.py` reads decoded frames of the file and writes `beat/checks/<rev16>/output-<file_sha16>.json`. It never reads `source.json`.
- A project declares its events in `tools_local/owners.py`: `EVENT_BINDS`, `COPY_BINDS`, `HUD_BINDS`. An event with no bind is UNVERIFIED, never skipped.

Tests: `python tools/tests/test_beat_check.py`, or `--quick` for logic only. Results: `stage1/phase2-checks.md`.

## What each run guarantees

- **A segment is reused only if its input key and complete profile match, and its bytes and rows still hash to what was published.** The key covers the beat, every owner that overlaps it, the shared parts of the page, the profile and the engine. A missing, damaged or stale `ownership.json` refuses the run, as does a file that differs from the map. A segment whose bytes moved counts as missing and renders again, named in the record's `damaged`.
- **A segment is published only after it is verified.** It is built in `beat/tmp/<run>/`, decoded in full, checked for frame count, packets and B-frames, and compared at every sample. A sample with no valid reference fails the round, as a bad one does. A crash leaves only `tmp/`, which the next run clears.
- **A reference is one of a set.** A page can keep what a frame it landed on did, so a beat's references are captured together in one session, seeking every frame from its first and photographing the samples, as its render reaches them. A receipt with no `stepped_from` is not valid, and one bad sample recaptures the set.
- **A region is local only if it is confined.** `confine.py` keeps anything off its short list in the shell, so its bytes are in every key. A block reads only its own names, the declared helpers, `tl` and `Math`, and writes no member.
- **Some things stop the build, because no hash of one block covers them:** a region that is not one balanced element, its scene's root. A region defining an id the shell holds or looks up. A tween or helper time that cannot be shown to be a number, and `tl` or a helper used other than by a direct call.
- **A killed run leaves nothing running.** Workers sit in a job object tied to `run.py`.
- **Stitching validates contents, not declared ranges:** key, profile, file hash, decoded count, stream parameters, then decoded rows and timestamps of the result, before the atomic rename.
- **The project must not move during a run.** `run.py` stamps it before and after, and publishes nothing if it changed.

## Renderer fault

The whole-render fault clips the composition to the top left 800x600 of the frame. `stage1/phase2-renderer.md` has how that was found and what is not known. Three layers guard against it, none a cure:

1. **Rotation.** A page is replaced at a beat boundary after `page_rotate_frames`, and inside a beat at twice that.
2. **The sentinel.** Every frame of every segment is screened for the clip signature. First, middle and last frame of each beat, plus each event frame and any suspect, are compared to a validated reference: whole frame, face half and the worst 48 px block. Anything below `PSNR_MIN` or over `BLOCK_MAX` is discarded and retried in a fresh session, twice at most. Then the run stops, with no partial segment.
3. **The viewport check.** Each beat's page must still report its full size when the beat ends.

Sampling cannot clear every frame. A defect that does not match the signature, and lasts less than the gap between samples, can pass. Each record states how many frames were not compared.

## Fault injection

Test only. Nothing a faulted attempt renders is ever published, and a run with `--inject-fault` stops before stitching.

```
python tools/beat_render/run.py draft <project> --profile review --workers 1 --inject-fault viewport --inject-beats b05
```

Kinds: `viewport` sets the page's viewport to 800x600, which gives the observed picture exactly. `dom` forces the video layers to 800x600 and hides the captions, with no viewport change. `crash` kills the browser mid-beat. `gpu` asks Chrome to crash its GPU process, and `clear` clears the override from a second CDP session. `--inject-rounds N` makes the fault last N attempts, so 3 proves the run stops.

## Qualification

```
python tools/beat_render/qualify.py range <project> --profile review --start 0 --end 3214 --workers 1 --rotate 0 --out DIR
python tools/beat_render/qualify.py sweep <project> --profile review --counts 2,4,6 --out FILE
```

`range` runs pages past anything a real beat reaches and compares every frame to the reference picture by decoded frame number. `sweep` times forced whole drafts.

Limits: integer frame rates, `profile.fps == lock.fps`, no alpha, HDR, deferred extraction, shader transitions or rational fps. `final-4k60` waits for Workstream E.

Beat starts use `common.source_frame_time(t, source_fps=30)` before `frame_of(..., fps)`: a final beat starts at its review frame times the integer rate factor. Review locks and segment keys stay unchanged. Animations and events retain their own frame timing. A derivative also snaps layout runs and full-face tags to that source grid; scene clip starts retain their source-grid snap.

`confine.frame_gaps(code, fps=60)` is advisory. It compares literal show/tween times and ivory's named arrival helpers, normalizes selector quotes, and checks child selectors and matching helper parameter expressions. It is not a JavaScript interpreter. `final.py` prints its findings on the derivative route as well as the kit's build warnings.
